How the detection work fits together

The detector scores each sentence and the report shows the share of a document that is likely AI-written. The hard part is not the classifier, it's the false positive: a student wrongly accused. So every change is judged first on how often it flags human writing, across many kinds of writers, and only then on how much more AI text it finds.

  • Mixed documents. Real submissions are rarely all human or all AI. Text-segmentation metrics such as WindowDiff, Pk and boundary similarity mix error types or score non-monotonically, and none handle several human/AI transitions per document with a tolerance. I designed five metrics that separate errors at the transitions (missed or misplaced boundaries) from errors away from them, with one matcher so the sentence and boundary readings agree. They justified moving production to a sentence-level model in 2026; until they existed, I held that release back.
  • Why detectors flag human writing. I traced false positives to the style of the writing rather than the writer, ruled out contamination and label noise, and built new training sets, including mined hard negatives, aimed at the gap. That research drives the next model.
  • The harness. The training and evaluation data have grown several times over in a year. That only works with a pipeline: a registry of more than a million documents that gates every new dataset (it found evaluation documents leaking into training), one validated schema for the datasets, configs for every run, and model cards generated from tracked runs, with no hand-typed numbers.
  • Agents with guardrails. For the latest model, agents integrated and checked data, launched and tracked training and evaluation jobs, compared candidates and prepared the deployment, with read-only cloud access and a person approving anything costly or irreversible. Shared documentation and per-stage agent skills onboard people and agents alike.
  • Earlier (2023–2024). Owned the evaluation pipeline for the detector's first releases, standardized sentence- and document-level metrics, wrote the model card that became the team's template, ran bias and fairness analyses, and evaluated competing detectors in four languages.

How the Clarity work was evaluated

Clarity shows teachers how a piece of writing came together, including when a student asked the AI assistant for help, and the assistant has to help without doing the work. Early baselines ran hundreds of submission and prompt pairs past more than a dozen LLM judges and code checks to rank models and prompts before choosing. The cost cut came from matching each task to the cheapest model that passed the same judges in each region, plus prompt changes (shorter targets, guidelines moved to the system message, prompt caching). Before that, in 2024, I built an agentic retrieval (RAG) demo that answered questions over about 400 scraped pages with citations, and document loaders for an internal prompt studio.

How each module works
  • Scan splitting. Splits a stack of scanned exams into one submission per student by matching each page to the template's pages with Siamese, set-based features. I rewrote most of it with four times the features per page, and its confidence decides between confirming the split, suggesting it, or falling back.
  • Alignment and masking. Aligns each scan to its template with a projective transform, filtering feature matches and keeping the best alignment, then masks the template away to leave student ink. New binarization handles shadows and coloured or textured paper, and masked files are about half the size.
  • Roster matching. Matches the handwritten name and student ID to the class roster. Training tricks taught it to say "not on the roster": removing the true entry, dropping the inferred name or ID, and dropping random entries, plus a softmax label for "not confident".
  • Handwriting recognition. CNN and bidirectional LSTM with CTC for single lines, with spatial transformers and curriculum learning from synthetic data, and a CV step that splits multi-line answers into lines.
  • Fast Transformer decoding (2020). The research model re-ran the whole decoder over the full prefix for every character. I wrote the inference path: one new token per step, a pre-allocated key-value cache, image features projected once for cross-attention, and an optional sliding window matching the training-time block attention. Per-step cost went from quadratic to linear in the output length (linear overall with the window), with tests asserting identical output. The paper's acknowledgements:
    "We would like to thank Saurabh Bipin Chandra for implementing the fast inference path (O(N²)) of the Transformer decoder, which was lacking in PyTorch."
    Libraries now ship the same ideas (for example Hugging Face's static cache, 2024).
  • Multiple choice. An inception-style fully convolutional network finds marks on full-resolution pages (thousands of pixels a side), where mark sizes vary widely, with a confidence model and a classifier for student ink in each bubble.
  • Blank answers and question types. A Siamese-style residual CNN detects blank answers even on misaligned pages (recall improved mostly by reviewing the data); a classifier labels question type and answer type.
  • Assignment template parser. Reads instructor PDFs (MuPDF, Mathpix for math and chemistry), finds headers and footers, and infers the question hierarchy with a penalty-based parser instead of hard rules. A confidence model halves the bad predictions shown to users.
  • Grading 10× faster. Supported the NSF SBIR project showing an AI could grade a new question after an instructor graded at most 10% of its answers.
